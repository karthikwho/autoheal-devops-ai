marked *request* can be pasted straight into `curl`.

## 1. Conventions

**Timestamps.** RFC 3339, UTC, `Z` suffix.

```json
"timestamp": "2026-10-09T12:00:00Z"
```

* Naive datetimes (`2026-10-09 12:00:00`) are rejected.
* Offset datetimes (`2026-10-09T14:00:00+02:00`) are accepted and normalised to UTC.
* Anything more than 300 seconds in the future is rejected.
* Every timestamp field is required to be timezone aware, in every model.

**Confidence.** A float in `[0.0, 1.0]` meaning *how strongly the diagnosis
module believes its own hypothesis*. It is not a probability that the fix will
work, and it says nothing about remediation safety. Below `0.5` forces
`requires_human_review = true`.

**Unknown keys are rejected.** All models use `extra="forbid"`. A typo in a
payload is a `422`, never a silently ignored field.

**Required vs optional.** A field is required unless it has a documented
default. `schema_version` defaults to the current contract version; everything
else in the lists below is required.

**Nullability.** Optional fields are `T | None` and serialise as `null`.

**About the examples.** Request payloads below are valid as written. Response
examples show the *shape* of the output; their timestamps are illustrative and
are generated by the service at request time.

## 2. `FailureEvent`

A normalised CI/CD failure. Produced by ingestion (Member 1); the request body
of `POST /api/v1/incidents`.

### Request example

```json
{
  "incident_id": "inc-20261008-ab12cd",
  "repository": "karthikwho/autoheal-devops-ai",
  "commit_sha": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0",
  "workflow_name": "ci",
  "run_id": 123456789,
  "failed_step": "pytest",
  "failure_type": "test_failure",
  "logs": "Run actions/checkout@v4\nRun pip install -e '.[dev]'\nFAILED tests/test_login.py::test_login_timeout - AssertionError: expected 200 got 500\n1 failed, 41 passed in 12.31s",
  "timestamp": "2026-10-08T09:14:22Z",
  "branch": "main",
  "pull_request_number": 7
}
```

> The `timestamp` is deliberately in the past: a timestamp more than 300 s in
> the future is rejected. When you paste this example, set it to the moment the
> failure actually happened.

### Fields

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `schema_version` | `"1.0"` | no | Must equal the current contract version. Defaults to `"1.0"`. |
| `incident_id` | `string` | **yes** | `^inc-[0-9]{8}-[0-9a-z]{6,12}$` |
| `repository` | `string` | **yes** | `owner/name`, 3–200 chars |
| `commit_sha` | `string` | **yes** | 7–64 hex chars; normalised to lower-case |
| `workflow_name` | `string` | **yes** | 1–200 chars, trimmed, non-empty |
| `run_id` | `integer` | **yes** | `>= 0`, `<= 2^63-1` |
| `failed_step` | `string` | **yes** | 1–200 chars, trimmed, non-empty |
| `failure_type` | `FailureType` | **yes** | One of the enum values in [§6](#6-enums) |
| `logs` | `string` | **yes** | 1–500 000 chars; must carry at least 10 significant characters |
| `timestamp` | `datetime` | **yes** | Timezone-aware UTC; not more than 300 s in the future |
| `branch` | `string \| null` | no | 1–200 chars |
| `job_name` | `string \| null` | no | 1–200 chars |
| `run_url` | `string \| null` | no | Must start with `https://`, max 500 chars |
| `pull_request_number` | `integer \| null` | no | `>= 1` |

### Notes

* `commit_sha` accepts upper-case input and stores lower-case.
* `logs` is **not** whitespace-normalised. It is trimmed at the ends only, so
  that `DiagnosisResult` evidence quotes remain byte-comparable against it.
* Platforms with a non-numeric run identifier must map it to a numeric pipeline
  id for `run_id`.
* Re-posting an existing `incident_id` returns `409 Conflict` from the API.

## 3. `DiagnosisResult`

An evidence-backed hypothesis. Produced by diagnosis (Member 2). **It is a
hypothesis, never proof that a repair is safe or verified.**

### Example

```json
{
  "schema_version": "1.0",
  "incident_id": "inc-20261009-ab12cd",
  "failure_type": "test_failure",
  "probable_cause": "The login handler raises after the token-refactor change",
  "evidence": [
    {
      "source": "failure_logs",
      "quote": "test_login_timeout",
      "explanation": "The failing assertion names the exact test that regressed",
      "log_offset": 214
    }
  ],
  "confidence": 0.62,
  "recommended_action": "fix_source_code",
  "risk_level": "medium",
  "requires_human_review": true,
  "limitations": "Only the pytest output was inspected; the source diff was not read.",
  "diagnosed_at": "2026-10-09T12:04:11Z",
  "diagnosis_producer": "anthropic/claude"
}
```

### Fields

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `schema_version` | `"1.0"` | no | Defaults to `"1.0"` |
| `incident_id` | `string` | **yes** | Must equal the `FailureEvent` incident id |
| `failure_type` | `FailureType` | **yes** | Must match the originating `FailureEvent` |
| `probable_cause` | `string` | **yes** | 10–1000 chars |
| `evidence` | [`EvidenceItem`] | **yes** | At least one item |
| `confidence` | `float` | **yes** | `0.0 <= confidence <= 1.0` |
| `recommended_action` | `RecommendedAction` | **yes** | Enum in [§6](#6-enums) |
| `risk_level` | `RiskLevel` | **yes** | Enum in [§6](#6-enums) |
| `requires_human_review` | `boolean` | **yes** | Forced to `true` in the cases below |
| `limitations` | `string` | **yes** | 10–2000 chars; always required |
| `diagnosed_at` | `datetime` | **yes** | Timezone-aware UTC, not in the future |
| `diagnosis_producer` | `string \| null` | no | Free-text producer label; provider neutral |

### `EvidenceItem`

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `source` | `EvidenceSource` | **yes** | Enum in [§6](#6-enums) |
| `quote` | `string` | **yes** | 3–4000 chars; exact substring of the named artefact |
| `explanation` | `string` | **yes** | 10–2000 chars |
| `log_offset` | `integer \| null` | no | `>= 0`; **only valid when `source` is `failure_logs`** |

### Evidence verification

When `source` is `failure_logs` and the originating `FailureEvent` is supplied,
the quote is checked byte-for-byte:

```python
from autoheal_contracts import DiagnosisResult, FailureEvent

event = FailureEvent.model_validate(failure_event_payload)
diagnosis = DiagnosisResult.model_validate(diagnosis_payload, context={"failure_event": event})
```

The following are `ValidationError`s:

* a `failure_logs` quote that is not present in `event.logs`;
* a `log_offset` that does not match the quote's real position;
* a `log_offset` on any other evidence source.

Reporting is honest by construction:

| Situation | Reported as |
| --- | --- |
| Log-sourced quote found in the logs | verified |
| Log-sourced quote absent from the logs | **unverified** (and rejected when validating with context) |
| Non-log source (e.g. `workflow_definition`) | `checked: false`, not a failure |
| Logs not supplied | `logs_available: false`, log-sourced quotes **unverified** |

Absence of logs is never counted as verification.

### Forced human review

`requires_human_review` must be `true` when any of these hold. The model
rejects the opposite.

| Condition | Reason |
| --- | --- |
| `risk_level` is `high` or `critical` | Dangerous to act unattended |
| `confidence < 0.5` | Not enough confidence to act unattended |
| `failure_type` is `unknown` | An unclassifiable failure is not understood |
| `recommended_action` is `escalate_to_human` | Escalation means a human, by definition |

## 4. `ValidationResult`

Proof that checks were re-run after a remediation attempt. **A proposed fix is
never a validated fix** — this model describes the second thing only.

### Example

```json
{
  "schema_version": "1.0",
  "incident_id": "inc-20261009-ab12cd",
  "passed": true,
  "tests_executed": 42,
  "tests_failed": 0,
  "failure_details": [],
  "validation_summary": "42 tests re-ran after the proposed fix; all reported pass.",
  "validated_at": "2026-10-09T12:30:00Z",
  "validation_scope": "test_suite",
  "command": "pytest -q",
  "environment": "ubuntu-latest",
  "duration_seconds": 12.34,
  "remediation_reference": "rem-0001"
}
```

### Fields

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `schema_version` | `"1.0"` | no | Defaults to `"1.0"` |
| `incident_id` | `string` | **yes** | Must equal the incident id |
| `passed` | `boolean` | **yes** | `true` requires executed, passing tests |
| `tests_executed` | `integer` | **yes** | `>= 0` |
| `tests_failed` | `integer` | **yes** | `>= 0`, `<= tests_executed` |
| `failure_details` | [`TestFailureDetail`] | no | `len <= tests_failed`; defaults to `[]` |
| `validation_summary` | `string` | **yes** | 10–2000 chars |
| `validated_at` | `datetime` | **yes** | Timezone-aware UTC, not in the future |
| `validation_scope` | `ValidationScope` | no | Enum in [§6](#6-enums); defaults to `test_suite` |
| `command` | `string \| null` | no | 1–200 chars |
| `environment` | `string \| null` | no | 1–200 chars |
| `duration_seconds` | `float \| null` | no | `>= 0` |
| `remediation_reference` | `string \| null` | no | Opaque reference to the remediation attempt |

### `TestFailureDetail`

| Field | Type | Required | Constraints |
| --- | --- | --- | --- |
| `test_name` | `string` | **yes** | 1–200 chars |
| `message` | `string \| null` | no | 1–2000 chars |
| `file_path` | `string \| null` | no | 1–200 chars |
| `line_number` | `integer \| null` | no | `>= 1` |

### Enforced invariants

* `tests_failed <= tests_executed`.
* **`passed = true` requires `tests_executed >= 1` and `tests_failed == 0`.**
  A suite that never ran cannot be reported as a pass.
* `len(failure_details) <= tests_failed` — details cannot invent failures.

### What this model does not mean

It does not mean the remediation was correct, minimal or safe. It means:
*these specific checks were re-executed after the change, and this is what
happened.* `is_recovery_verified` is `true` only when `passed` is `true`,
`tests_executed > 0` and `tests_failed == 0`.

## 5. `IncidentRecord`

The aggregate: failure event, optional diagnosis, optional validation,
lifecycle status and timestamps.

### Example

```json
{
  "schema_version": "1.0",
  "incident_id": "inc-20261009-ab12cd",
  "failure_event": { "...": "see §2" },
  "diagnosis": null,
  "validation": null,
  "status": "received",
  "created_at": "2026-10-09T12:01:00Z",
  "updated_at": "2026-10-09T12:01:00Z",
  "status_history": [
    { "status": "received", "at": "2026-10-09T12:01:00Z", "note": null }
  ]
}
```

### Fields

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `schema_version` | `"1.0"` | no | Defaults to `"1.0"` |
| `incident_id` | `string` | **yes** | Must match every embedded payload |
| `failure_event` | `FailureEvent` | **yes** | Always present |
| `diagnosis` | `DiagnosisResult \| null` | no | Required once the status says so |
| `validation` | `ValidationResult \| null` | no | Required once the status says so |
| `status` | `IncidentStatus` | **yes** | Defaults to `received` |
| `created_at` | `datetime` | **yes** | `>= failure_event.timestamp` |
| `updated_at` | `datetime` | **yes** | `>= created_at` |
| `status_history` | [`StatusTransition`] | **yes** | Starts at `received`, ends at `status` |

`StatusTransition` is `{ "status": IncidentStatus, "at": datetime, "note": string | null }`.

### Status preconditions

A status may never claim more than the record carries.

| Status | Requires |
| --- | --- |
| `received` | A `failure_event`, and **no** diagnosis |
| `diagnosed` | A diagnosis |
| `awaiting_review` | A diagnosis requiring human review |
| `remediation_proposed` | A diagnosis |
| `remediation_approved` | A diagnosis, approved by a human |
| `validating` | A diagnosis and an approved remediation |
| `validated` | A **passing** validation result |
| `validation_failed` | A **failing** validation result |
| `escalated` | A diagnosis, escalated to a human |
| `resolved` | A **passing** validation result |
| `closed` | A **passing** validation result |
| `abandoned` | Nothing (the only escape hatch) |

### Lifecycle helpers

```python
record = IncidentRecord.from_failure_event(event)          # -> received
record = record.attach_diagnosis(diagnosis)                # -> diagnosed | awaiting_review
record = record.attach_validation(validation)              # -> validated | validation_failed
```

Payload and status are applied in a **single re-validation**, so a record can
never be observed in a state where the status asserts something the payload
does not support. Every helper returns a new instance; the original is
untouched.

Derived properties: `is_terminal`, `is_recovery_verified`, `needs_human_review`.

## 6. Enums

### `FailureType`

| Value | Meaning |
| --- | --- |
| `test_failure` | A test failed |
| `lint_format` | Lint or formatting check failed |
| `build_compilation` | Compilation or build step failed |
| `dependency_resolution` | Dependencies could not be resolved |
| `dependency_vulnerability` | A dependency audit found a vulnerability |
| `configuration` | Pipeline or project configuration is wrong |
| `timeout` | The run exceeded its time budget |
| `flaky_test` | An intermittently failing test |
| `infrastructure` | Runner or executor infrastructure failure |
| `authentication_permissions` | Credentials, tokens or scopes |
| `security_scan` | A security scanner gate failed |
| `unknown` | Could not classify — routes to human review |

### `RiskLevel`

`low` · `medium` · `high` · `critical`

`high` and `critical` always force `requires_human_review`.

### `RecommendedAction`

`retry_job` · `rerun_tests` · `pin_dependency` · `update_dependency`
· `fix_source_code` · `fix_configuration` · `revert_commit` ·
`escalate_to_human` · `no_action`

These describe *categories* of response. They are never concrete commands;
AutoHeal does not execute arbitrary shell input.

### `EvidenceSource`

`failure_logs` · `workflow_definition` · `source_diff` · `repository_file` ·
`dependency_manifest` · `test_report` · `platform_metadata` ·
`external_reference` · `inferred_no_source`

Only `failure_logs` quotes are checked against the log. `inferred_no_source`
is the honest option for a conclusion with no artefact behind it.

### `ValidationScope`

`test_suite` · `single_test` · `lint` · `build` · `smoke` · `full_pipeline`

### `IncidentStatus`

`received` · `diagnosed` · `awaiting_review` · `remediation_proposed` ·
`remediation_approved` · `validating` · `validated` · `validation_failed` ·
`escalated` · `resolved` · `closed` · `abandoned`

## 7. HTTP endpoints

Base URL in development: `http://127.0.0.1:8000`.

### `GET /health`

Liveness. Performs no I/O of its own, so it stays cheap enough for an uptime
probe.

```bash
curl -sS http://127.0.0.1:8000/health
```

```json
{
  "status": "healthy",
  "service": "autoheal-api",
  "version": "0.1.0",
  "contract_schema_version": "1.0",
  "store": "json_file",
  "incidents": 0,
  "time": "2026-10-09T12:00:00.123456Z"
}
```

### `GET /api/v1/incidents`

A page of incident summaries, newest **failure** first.

Query parameters: `status`, `repository`, `limit` (default 50, max 200),
`offset` (default `0`), `order` (`asc` | `desc`, default `desc`).

```bash
curl -sS 'http://127.0.0.1:8000/api/v1/incidents?status=received&limit=2'
```

```json
{
  "items": [
    {
      "incident_id": "inc-20261009-ab12cd",
      "status": "received",
      "repository": "karthikwho/autoheal-devops-ai",
      "workflow_name": "ci",
      "failure_type": "test_failure",
      "created_at": "2026-10-09T12:01:00Z",
      "updated_at": "2026-10-09T12:01:00Z",
      "diagnosis_attached": false,
      "validation_attached": false,
      "recovery_verified": false
    }
  ],
  "pagination": { "limit": 2, "offset": 0 },
  "total": 1
}
```

An empty `items` array is a valid response: a freshly started service has no
incidents.

### `GET /api/v1/incidents/{incident_id}`

One full record, or `404`.

```bash
curl -sS http://127.0.0.1:8000/api/v1/incidents/inc-20261009-ab12cd
```

Returns the full [`IncidentRecord`](#5-incidentrecord) (§5 example shape) or:

```json
{
  "error": {
    "code": "incident_not_found",
    "message": "no incident with id 'inc-20261001-zzzzzz'",
    "details": { "incident_id": "inc-20261001-zzzzzz" }
  }
}
```

### `POST /api/v1/incidents`

Create an incident from a validated `FailureEvent`.

```bash
curl -sS -X POST http://127.0.0.1:8000/api/v1/incidents \
  -H 'Content-Type: application/json' \
  -d @docs/examples/failure-event.json
```

`201 Created` with a `Location` header pointing at the new resource, and the
created `IncidentRecord` as the body.

```json
{
  "schema_version": "1.0",
  "incident_id": "inc-20261009-ab12cd",
  "failure_event": { "...": "the posted FailureEvent, normalised" },
  "diagnosis": null,
  "validation": null,
  "status": "received",
  "created_at": "2026-10-09T12:01:00Z",
  "updated_at": "2026-10-09T12:01:00Z",
  "status_history": [
    { "status": "received", "at": "2026-10-09T12:01:00Z", "note": null }
  ]
}
```

| Status | When |
| --- | --- |
| `201` | Created |
| `409` | `incident_id` already exists |
| `422` | Payload violates the contracts |

Nothing is persisted when the payload is invalid.

## 8. Errors

All non-2xx responses share one envelope.

```json
{
  "error": {
    "code": "contract_violation",
    "message": "The payload does not satisfy the AutoHeal contracts.",
    "details": {
      "errors": [
        { "field": "body.failure_type", "type": "enum", "message": "Input should be ..." }
      ]
    }
  }
}
```

| HTTP | `code` | Cause |
| --- | --- | --- |
| `404` | `incident_not_found` | Unknown incident id |
| `409` | `incident_already_exists` | Duplicate `incident_id` on create |
| `422` | `contract_violation` | Payload failed contract validation, or a query parameter was out of range |

Branch on `code`, never on `message`.

## 9. Schema versioning

Every contract carries `schema_version`, currently `"1.0"`. The field is
constrained to the exact current value, so a payload from a different revision
fails loudly instead of being misread.

**Current version: `1.0`**

| Version | Status | Notes |
| --- | --- | --- |
| `1.0` | Current | Initial contracts: `FailureEvent`, `DiagnosisResult`, `ValidationResult`, `IncidentRecord` |

Rules for the next revision:

* **Adding an optional field** is backwards compatible. Ship it as `T | null`
  with a default, bump the minor (`1.1`), no migration needed.
* **Removing or renaming a field, tightening a constraint, or changing a
  meaning** is breaking. Bump the major (`2.0`).
* A breaking bump must add a migration note here, keep the previous version
  parseable by the old models where practical, and land with a test that shows
  old payloads failing *clearly* rather than silently.
* Never widen `enum` values silently: a new `FailureType` member changes
  behaviour in every consumer that maps it.

`GET /health` reports `contract_schema_version`, so a deployment can be checked
for drift against the contracts it was built against.
